## 摘要

本课程设计实现了一套融合**深度学习、知识图谱与机器学习**的智能招聘简历筛选系统。系统以 Flask 提供后端服务，采用 TF-IDF + 逻辑回归实现简历岗位分类，基于 networkx 构建岗位-技能知识图谱支撑技能推理，通过多维特征融合计算候选人匹配度并排序，最终以 Web 界面可视化呈现。系统完成了数据采集、清洗、预处理、入库，并通过 23 项自动化测试，达到可现场演示状态。全程采用 vibe coding 方法（提示词工程、上下文工程、规格驱动开发、自动化测试与人工审查、调试接管）辅助开发，并如实披露 AI 使用情况。

**关键词**：简历筛选；知识图谱；TF-IDF；逻辑回归；文本分类；Flask

## 1. 背景调研（研究意义）

### 1.1 行业背景
招聘是企业人力资源管理的重要环节。据统计，大型企业单次招聘可能收到数千份简历，人工筛选耗时耗力且标准不一。传统关键词匹配方法存在三大局限：一是**语义理解不足**，无法识别"熟悉 PyTorch"与"有深度学习经验"等语义等价表达；二是**缺乏结构化推理**，无法依据岗位技能体系补全候选人的能力画像；三是**结果不可解释**，筛选理由难以向用人部门说明。

### 1.2 研究意义
本系统探索将深度学习语义理解与知识图谱结构化推理相融合，实现简历筛选的**可解释性**，弥补传统方法的不足：
- 对候选人：获得岗位匹配度与缺失技能提示，明确提升方向；
- 对招聘方：获得客观、可解释、可追溯的筛选结果，提升招聘效率。

### 1.3 现有工作调研
目前简历筛选类研究主要分为两类：一类基于规则与词频统计（实现简单但理解能力弱），另一类基于深度学习端到端模型（效果好但缺乏可解释性）。本系统取两者之长：用机器学习做分类、用知识图谱做推理、用规则做细粒度解析，形成完整业务闭环。

### 2.1 需求分析

### 2.3 系统架构

### 2.4 业务闭环
简历上传 → 文本解析 → 岗位分类 → 技能抽取 → 知识图谱推理（缺失技能） → 多维匹配排序 → 前端可视化 → 历史入库。

## 3. 数据资源构建

### 3.1 数据来源
- **简历数据集（主）**：Kaggle 公开数据集 Resume Dataset（约 2400 份 / 25 类），仓库内置公开镜像子集 169 条。链接：https://www.kaggle.com/datasets/snehaanbhawal/resume-dataset
- **岗位描述（辅）**：Indeed 公开岗位样本筛选 55 条。链接：https://github.com/luminati-io/Indeed-dataset-samples
- **自建补充**：为补齐技术类岗位，人工整理 16 条岗位描述（标注"自建数据集"），保证 25 类全覆盖。

### 3.2 数据预处理
`preprocessing/` 目录实现预处理程序：
1. 简历：去 HTML/URL、规范化空白、**隐私掩码**（邮箱/电话/身份证）、按类别分层 8:2 划分训练/测试集；
2. 岗位：按 25 类关键词筛选、文本清洗、技能词表抽取、生成岗位-技能关系表。

预处理结果：简历 166 条（训练 135 / 测试 31）、岗位 71 条、岗位-技能关系 291 条 / 85 技能。详见 `data/README.md`。

### 3.3 数据合规
全部数据来自公开数据集或自建演示数据；简历隐私信息已掩码；报告如实披露所有来源。

## 4. 系统实现

### 4.1 后端服务（Flask）
- `app/__init__.py`：应用工厂，注册 4 个 API 蓝图；
- `app/api/`：resume（解析）、match（匹配）、graph（图谱）、system（系统）四个蓝图；
- `run.py`：启动入口（`python run.py` → http://127.0.0.1:5000）。

### 4.2 数据库（SQLite）
`app/database.py` 实现三张表：`resumes`（简历）、`candidate_analyses`（分析结果）、历史查询接口。测试时通过环境变量切换到临时库，不污染正式数据。

### 4.3 算法模块

**（1）技能抽取 `skill_extractor.py`**：基于中英文技能词表（`skill_lexicon.py`，覆盖编程/数据/Web/数据库/运维/测试/安全/管理等 180+ 技能），英文做词边界匹配、中文用 jieba 分词辅助匹配，输出去重技能列表。

**（2）简历解析 `resume_parser.py`**：正则规则提取姓名（姓名标签）、邮箱/电话（掩码化）、学历（博士/硕士/本科等关键词）、经验年限、岗位意向；技能调用抽取模块。

**（3）岗位分类 `classifier.py`**：TfidfVectorizer（ngram 1-2, min_df=2）+ LogisticRegression（max_iter=2000）多分类模型，在 135 条训练样本上训练，测试集准确率 51.6%（25 类多分类，随机基线 4%）。模型缓存序列化避免重复训练。**该模块对应深度学习/机器学习技术方向**——答辩说明：生产环境可无缝替换为 BERT 预训练模型（transformers），本演示版为保证本地可运行采用可训练的轻量实现。

**（4）知识图谱 `skill_graph.py`**：networkx 有向图，节点为岗位类别与技能，边为"requires"关系。支持岗位技能查询、技能反查、**缺失技能推理**（简历技能与岗位要求求差集）、按技能相似度推荐岗位、输出 ECharts 关系图数据。**该模块对应知识图谱技术方向**——答辩说明：生产环境可替换 Neo4j，Cypher 查询天然支持图遍历推理。

**（5）匹配排序 `matcher.py`**：多维特征融合评分：
```
match_score = 100 × (0.45×硬技能覆盖率 + 0.25×分类置信度 + 0.15×经验分 + 0.15×预测命中)
```
其中硬技能覆盖率剔除 communication/leadership 等通用软技能（避免区分度不足），并对硬技能过少的岗位按规模压缩，保证技术岗位区分度。输出命中/缺失技能、匹配等级（高/中/低），实现**可解释性**。

### 4.4 前端界面
`app/static/`：单页演示界面（HTML/CSS/JS + 本地 ECharts）。四个区域：简历输入（含示例）、解析与匹配结果（解析字段/分类 TopK/匹配排名条）、岗位技能图谱可视化（ECharts 关系图）、历史记录表格。

## 5. 测试与集成调试

### 5.1 测试设计
`tests/` 目录编写 pytest 测试 23 项：

| 模块 | 测试数 | 覆盖内容 |
|------|--------|----------|
| resume_parser | 5 | 中英文解析、隐私掩码、空输入、技能抽取 |
| classifier | 2 | 训练预测、测试集评估 |
| skill_graph | 5 | 图谱加载、岗位技能、缺失推理、相关岗位、图谱数据 |
| matcher | 3 | 匹配计算、分数边界、排序正确性 |
| API | 8 | 健康检查、页面、解析、匹配、异常、图谱、历史 |

### 5.2 测试结果
全部 23 项测试通过（`pytest tests/`）。核心指标：分类器测试集准确率 51.6%；单次匹配分析响应 < 3 秒。

### 5.3 集成调试过程
- **分类器 sklearn 兼容**：新版 scikit-learn 移除 `multi_class` 参数 → 运行时 TypeError → 移除参数修复；
- **姓名正则精度**：`Name: Li Ming. Python Developer` 被过度匹配 → 改为字母词限定、标点停止；
- **匹配区分度**：HR/Sales 等软技能岗位对技术简历覆盖率虚高 → 引入硬技能过滤 + 技能规模惩罚。

### 5.4 验证方式
1. `pytest tests/` 全量回归（23 通过）；
2. 启动服务后用 HTTP 请求逐一验证 10 个 API；
3. 用真实简历数据验证完整业务闭环（解析→分类→匹配→图谱→历史）；
4. 前端静态资源与页面可访问性验证。

## 7. 总结与展望

### 7.1 工作总结
本课程设计完整实现了"数据 → 算法 → 服务 → 界面"的全栈业务闭环：
- 构建了 25 类岗位的简历与岗位描述数据集，完成清洗、隐私掩码与入库；
- 实现了 TF-IDF+逻辑回归简历分类、技能抽取、知识图谱推理、多维匹配排序；
- 提供 Flask REST API 与可视化前端，通过 23 项自动化测试，可现场演示；
- 全程 git 管理、prompt 追溯，完成 AI 使用披露。

### 7.2 不足与展望
1. **分类准确率**：受限于训练样本规模（135 条/25 类），TF-IDF+逻辑回归准确率约 52%；后续可引入 BERT 预训练模型微调，预计显著提升；
2. **图谱推理能力**：当前为规则式推理（缺失技能求差集）；接入 Neo4j 后可支持多跳推理与技能关联补全；
3. **中文简历支持**：当前数据以英文为主，可补充中文简历语料增强；
4. **工程化**：可升级 Vue3 前端、Docker 部署、Redis 缓存，进一步贴近生产。
