# 答辩自述讲稿（3 分钟 / 约 700 字）

> 对应《答辩PPT v2》（10 页），按正常语速约 3 分钟。答辩前建议照读 2-3 遍计时，练到自然流畅；数字（55.84 / 87.5% / 0.45 权重等）要能脱口而出，问答环节老师很可能追问。

## 开场 · 封面（约 10 秒）

各位老师好，我是×××，我课程设计的题目是《基于深度学习与知识图谱的智能招聘简历筛选系统设计与实现》。下面我从背景调研、方案设计、数据资源构建、详细开发内容、调试与总结展望六个方面进行汇报。

## 汇报提纲（约 10 秒）

整个系统围绕"如何用技术手段解决简历筛选效率低、标准不一的问题"展开，最终交付了一个可现场演示的完整系统。

## 背景调研 · 研究意义（约 30 秒）

先说背景。数字化招聘普及后，企业收到的简历量激增，传统人工筛选面临两个突出问题：一是效率低，筛选占用了 HR 大量时间；二是标准不统一，容易漏筛优质候选人。因此，本课题的研究意义在于：用自然语言处理实现简历的自动化解析和岗位分类，用知识图谱支撑技能缺口推理，最终提升人岗匹配的效率和客观性。

## 方案设计（约 35 秒）

方案设计上，我覆盖了四个技术方向：深度学习方向，在演示版中用 TF-IDF 加逻辑回归实现简历的岗位自动分类，覆盖 25 类岗位；知识图谱方向，用 networkx 构建岗位与技能的有向图，支撑技能缺口推理；机器学习方向，用多维加权匹配模型对候选人做匹配度排序；Web 开发方向，用 Flask 加静态前端实现整个演示系统。系统整体分为前端、服务、算法、数据四层。

## 数据资源构建（约 25 秒）

数据方面，简历主数据集采用 Kaggle 公开的 Resume Dataset，仓库内置了覆盖全部 25 类的镜像子集；岗位数据采用 Indeed 公开样本，并自建补充了 16 条。预处理后，简历清洗为 166 条，划分训练集 135 条、测试集 31 条；岗位 71 条、岗位技能关系 291 条，同时执行了邮箱、电话、身份证的隐私掩码。

## 系统实现（约 25 秒）

系统实现上，后端用 Flask 提供四组 REST 接口，数据库用 SQLite 存储匹配历史和图谱数据，前端用静态页面加 ECharts 做可视化。业务流程从简历上传、文本解析、岗位分类、技能抽取、图谱推理、匹配排序，到前端可视化和历史入库，形成了完整闭环。

## 算法模块（约 30 秒）

核心算法有三个：岗位分类用 TF-IDF 文本向量化加逻辑回归；知识图谱用 networkx 有向图存储岗位与技能的依赖关系，对候选人做差集推理得到缺失技能；匹配模型按技能覆盖、分类置信度、经验匹配、预测命中四个维度加权，权重分别是 0.45、0.25、0.15 和 0.15，得到匹配分数并划分高、中、低三个等级。

## 调试与测试（约 25 秒）

测试方面，我为系统写了 23 项 pytest 自动化测试并全部通过，覆盖解析、分类、图谱、匹配和 API 五个模块；10 组 REST 接口都做了实测。集成调试通过一键启动脚本和健康检查，前端后端联调正常，达到了可现场演示的状态。演示时用示例简历匹配 Python Developer 岗位，得到匹配分 55.84、技能覆盖率 87.5%。

## 总结展望（约 15 秒）

总结来说，系统完成了四层架构和完整业务闭环，四个技术方向都实际落地，全程使用 git 版本管理并保留了过程档案。不足方面，分类器基于小样本训练，准确率有限，后续计划引入预训练语言模型提升精度，并扩展知识图谱规模。

## 结尾 · 致谢（约 10 秒）

我的汇报到此结束，系统可以现场一键启动演示，代码和演示视频都在 GitHub 仓库，欢迎各位老师批评指正，谢谢！
